# 모아 — GitHub 연동 가계부

파란색 테마의 개인용 웹 가계부입니다. 웹 화면은 GitHub Pages에서 제공하고, 수입·지출 데이터는 별도의 **비공개 GitHub 저장소**에 JSON 파일로 저장합니다. 별도 애플리케이션 서버를 운영하지 않습니다.

## 1. 파일과 저장소 구성

| 위치 | 파일 | 역할 |
|---|---|---|
| 공개 웹사이트 저장소 | `index.html` | GitHub 연결 및 로컬 연결 정보 관리 |
| 공개 웹사이트 저장소 | `ledger.html` | 캘린더, 수입·지출 입력, 날짜별 목록 |
| 공개 웹사이트 저장소 | `README.md` | 설치·사용 설명서 |
| 비공개 데이터 저장소 | `2026.json`, `2027.json` 등 | 연도별 거래 데이터 |

**두 HTML 파일은 같은 폴더에 두세요.** 파일 이름의 대소문자와 확장자를 그대로 유지해야 페이지 이동이 작동합니다. 배포할 때 `index (1).html`이나 `index.html.txt`로 이름이 바뀌지 않았는지 확인하세요.

이 문서의 `your-github-id`는 설명용 가상 아이디입니다. 실제 설정에는 본인의 GitHub 아이디를 입력합니다.

## 2. 제공 기능

- GitHub 연결, 연결 해제, 저장, 불러오기
- 연결 화면에서 새 JSON 파일 생성
- 아이디·저장소·토큰의 선택적 기기 저장 및 삭제
- 현재 연도를 기준으로 한 JSON 파일 기본값
- 월간 캘린더, 이전·다음 달 이동, 오늘 이동
- 캘린더와 입력 날짜의 양방향 연동
- 지출·수입 버튼으로 입력 영역 열기·접기
- 날짜·금액·분류·내용 입력과 금액의 천 단위 쉼표
- 선택한 날짜의 거래 목록과 건수 표시
- 연도 전환 시 해당 파일 확인, 생성 또는 불러오기와 팝업 안내
- 미저장 내역 확인 및 저장 충돌 시 덮어쓰기 차단

## 3. GitHub 연결 준비 — 전체 순서

1. 웹사이트용 공개 저장소를 만듭니다.
2. 두 HTML 파일을 올리고 GitHub Pages를 설정합니다.
3. 데이터용 비공개 저장소를 만들고 README를 추가합니다.
4. 비공개 데이터 저장소에 접근할 토큰을 발급합니다.
5. 가계부 사이트에서 연결 정보를 입력합니다.
6. 처음이라면 JSON 파일을 생성하고, 기존 파일이 있다면 불러옵니다.

### 3-1. 웹사이트용 공개 저장소 만들기

1. GitHub 로그인 후 [새 저장소 만들기](https://github.com/new)를 엽니다.
2. **Owner**에서 본인 계정을 선택합니다.
3. **Repository name**에 `daily_acc`를 입력합니다. 다른 이름을 사용해도 됩니다.
4. 공개 범위를 **Public**으로 선택합니다.
5. **Add README**를 켜고 **Create repository**를 누릅니다.
6. 저장소의 **Code → Add file → Upload files**에서 `index.html`과 `ledger.html`을 업로드합니다.
7. **Commit changes**로 확정합니다. 이 README도 같은 위치에 올릴 수 있습니다.

실제 거래 데이터와 토큰은 이 공개 저장소에 올리지 마세요.

### 3-2. GitHub Pages 켜기

저장소의 **Settings → Pages → Build and deployment**에서 설정합니다.

| 항목 | 선택값 |
|---|---|
| Source | Deploy from a branch |
| Branch | `main` — 실제 파일을 올린 브랜치 |
| Folder | `/(root)` |

**Save**를 누르고 배포를 기다립니다. **Actions** 탭에서 배포 결과를 확인하고, **Settings → Pages → Visit site**로 접속하세요. 메뉴 이름은 GitHub UI 업데이트에 따라 조금 달라질 수 있습니다.

저장소 이름이 `daily_acc`라면 주소 형식은 `https://<본인아이디>.github.io/daily_acc/`입니다. 이 주소는 `index.html`을 기본으로 표시합니다. 주소창에 파일 이름이 붙지 않아도 정상입니다.

설정 기준: [GitHub Pages 배포 소스 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

### 3-3. 데이터용 비공개 저장소 만들기

[새 저장소 만들기](https://github.com/new)에서 별도의 저장소를 만듭니다.

| 항목 | 입력·선택 예시 |
|---|---|
| Owner | 본인 계정 |
| Repository name | `household-ledger-data` |
| Visibility | **Private** |
| Add README | **켜기** |

**Create repository**를 누른 뒤 이름 옆에 **Private** 표시가 있는지 확인합니다.

README를 추가해야 초기 커밋과 기본 브랜치가 만들어집니다. 현재 앱은 기존 브랜치에 JSON 파일을 생성하므로, 완전히 빈 저장소라면 README부터 추가해야 합니다. 이 저장소에는 GitHub Pages를 설정하지 않습니다.

JSON 파일은 가계부 사이트에서 생성할 수 있으므로 지금 직접 만들 필요는 없습니다.

### 3-4. GitHub 접근 토큰 발급하기

[Fine-grained 토큰 발급 페이지](https://github.com/settings/personal-access-tokens/new)를 엽니다. 직접 이동하려면 프로필 메뉴의 **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**을 선택합니다.

| 항목 | 설정 |
|---|---|
| Token name | `모아 가계부` 등 알아보기 쉬운 이름 |
| Expiration | 사용할 만료일 선택 |
| Resource owner | 비공개 데이터 저장소를 소유한 본인 계정 |
| Repository access | **Only select repositories** |
| Selected repositories | **`household-ledger-data` 등 비공개 데이터 저장소** |
| Repository permissions → Contents | **Read and write** |
| Metadata | 자동 포함되는 Read-only 권한 유지 |

**웹사이트 저장소 `daily_acc`가 아니라 실제 데이터를 보관할 비공개 저장소를 선택하세요.** 개인 소유 저장소 기준 설명이며 조직 저장소는 별도 승인이 필요할 수 있습니다.

**Generate token**을 누른 뒤 발급된 토큰을 복사합니다. 비밀번호 관리자 등에 안전하게 보관하고 공개 코드·JSON 파일·스크린샷에 포함하지 마세요. 토큰을 잃어버렸거나 만료되면 새 토큰을 발급해 입력합니다.

설정 기준: [GitHub 개인 접근 토큰 공식 안내](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).

### 3-5. 가계부 사이트에서 연결하기

배포한 사이트의 첫 화면에 다음 정보를 입력합니다.

| 입력칸 | 예시·설명 |
|---|---|
| GitHub 아이디 | 본인의 아이디 |
| 비공개 데이터 저장소 | `household-ledger-data` |
| 브랜치 | `main` 또는 해당 저장소의 실제 브랜치 |
| JSON 파일 경로 | 현재 연도의 파일, 예: `2026.json` |
| 접근 토큰 | 앞에서 발급한 토큰 |

파일 기본값은 **브라우저가 인식한 현재 연도 + `.json`**입니다. 2027년에 접속하면 기본값은 `2027.json`입니다. 과거 파일을 열려면 직접 경로를 수정할 수 있습니다.

- **파일이 있는 경우:** `연결하고 시작하기`를 누릅니다.
- **파일이 없는 경우:** `새 파일 만들기`를 누르고 빈 가계부 생성 팝업을 확인합니다.

성공하면 `ledger.html`로 이동하고 맨 위에 **GitHub 연결됨**과 연결된 파일 경로가 표시됩니다. 처음 연결할 때 `연결하고 시작하기`만 눌러서는 없는 파일을 생성하지 않습니다. 생성 버튼을 사용하세요.

직접 JSON 파일을 만들고 싶다면 비공개 저장소에서 **Add file → Create new file**을 누르고, 파일 이름을 `2026.json`처럼 지정한 후 다음 내용을 커밋합니다.

```json
{
  "version": 1,
  "currency": "KRW",
  "transactions": []
}
```

### 3-6. 아이디·저장소·토큰을 이 기기에 저장하기

- **이 기기에 저장:** 입력한 아이디·저장소·토큰을 이 브라우저의 `localStorage`에 보관합니다.
- **이 기기에 아이디·저장소·토큰 저장:** 체크한 상태로 연결에 성공해도 해당 정보가 저장됩니다.
- **체크 해제:** 기존 로컬 저장 정보를 삭제합니다.
- **저장 정보 삭제:** 로컬 연결 정보와 현재 탭의 연결 세션을 삭제하고 입력칸을 비웁니다.

저장 정보가 있으면 다음 방문에 자동으로 채워집니다. 자동 로그인이나 자동 연결은 아니며, 연결 버튼을 눌러야 합니다. 로컬 저장 대상은 아이디·저장소·토큰이며, JSON 경로는 매번 올해 연도를 기본으로 합니다.

**토큰은 암호화 없이 브라우저에 저장됩니다.** 개인 기기에서만 사용하세요. 기기 저장을 선택하지 않아도 두 페이지를 이동하기 위해 현재 탭의 `sessionStorage`에 연결 정보를 보관합니다.

가계부의 **연결 해제**는 탭 세션만 삭제합니다. 기기에 저장한 정보까지 없애려면 연결 화면에서 **저장 정보 삭제**를 누르세요. 이 기능은 GitHub 토큰 자체를 폐기하지 않습니다. 토큰 폐기는 GitHub 설정에서 수행합니다.

## 4. 수입·지출 입력과 저장

1. 캘린더에서 날짜를 선택합니다.
2. 캘린더 아래 **지출** 또는 **수입** 버튼을 누릅니다.
3. 날짜·금액·분류·내용을 입력합니다. 날짜를 직접 바꾸면 캘린더도 연동됩니다.
4. **지출 추가 / 수입 추가**를 누릅니다.
5. 아래의 선택 날짜 목록에서 내용과 금액을 확인합니다.
6. 맨 위 **GitHub 저장**을 누릅니다.

같은 종류 버튼을 다시 누르면 입력 폼이 접힙니다. 다른 종류 버튼을 누르면 해당 폼으로 전환됩니다. 접어도 입력 중인 내용은 유지됩니다. 지출·수입을 전환할 때 금액·내용은 유지되고 분류 목록이 바뀌므로 추가 전에 확인하세요.

금액은 `12,000`처럼 표시되지만 JSON에는 숫자로 저장됩니다. 지원 범위는 1원부터 1조 원까지의 정수입니다.

**‘내역 추가’와 ‘GitHub 저장’은 다릅니다.** 입력칸만 채운 상태에서 GitHub 저장을 누르면 그 작성 중인 내용은 포함되지 않습니다. 먼저 내역 추가를 누르세요. 거래 내역은 로컬에 자동 백업되지 않습니다.

## 5. 연도가 바뀔 때

캘린더 이동이나 날짜 선택으로 다른 연도로 이동하면 같은 저장소·브랜치에서 해당 연도의 파일을 확인합니다.

| 상태 | 동작 |
|---|---|
| `2027.json`이 있음 | 팝업 확인 후 파일을 불러옴 |
| `2027.json`이 없음 | 팝업 확인 후 빈 JSON 파일을 생성하고 불러옴 |
| 기존 연도에 미저장 내역이 있음 | 확인 후 기존 연도 파일에 먼저 저장하고 전환 |
| 입력칸에 작성 중인 금액·내용이 있음 | 내용을 유지하고 선택 날짜를 변경 |
| 팝업에서 취소 | 기존 연도와 날짜 유지 |
| 권한·네트워크·저장 충돌 오류 | 오류 안내 후 기존 연결 유지 |

현재 경로가 `data/2026.json`이면 다음 연도 파일도 `data/2027.json`으로 생성됩니다. 과거의 `ledger.json`처럼 여러 연도를 담은 파일을 자동으로 분리하거나 이전하지는 않습니다.

## 6. 불러오기와 저장 충돌

**불러오기**는 현재 연결된 JSON의 최신 내용을 가져옵니다. 미저장 내역이나 작성 중인 내용이 있으면 버릴지 확인합니다.

다른 기기에서 파일을 변경했다면 저장 시 파일 버전이 달라져 덮어쓰기를 중단합니다. 현재 앱에는 자동 병합과 백업 내보내기 기능이 없으므로, 필요한 미저장 내용을 별도로 기록한 뒤 최신 데이터를 불러와 다시 입력하세요.

네트워크 오류로 저장 결과를 확인하지 못했을 때는 GitHub에서 실제 파일을 확인하세요. 재시도나 불러오기에 앞서 미저장 내용을 보존하는 것이 좋습니다.

## 7. 자주 발생하는 문제

| 증상 | 확인할 내용 |
|---|---|
| Pages 주소에서 404 표시 | 파일 이름이 정확히 `index.html`인지, 배포 브랜치 최상위에 있는지, Pages가 같은 브랜치와 `/(root)`를 가리키는지 확인 |
| 이전 화면이 계속 표시 | Actions 배포 완료 후 새로고침. 필요하면 강력 새로고침 |
| 가계부 페이지에서 연결 페이지로 돌아감 | 탭 연결 세션이 없거나 읽을 수 없는 상태. 첫 페이지에서 다시 연결 |
| 401 오류 | 토큰 만료·오타·폐기 여부 확인 |
| 403 오류 | Contents 권한, 조직 승인, API 사용 제한 확인 |
| 404 오류 | 아이디·저장소·브랜치·파일 경로와 토큰에 선택된 저장소 확인. 권한 부족도 404로 보일 수 있음 |
| 브랜치를 확인할 수 없음 | 빈 저장소라면 README 추가. 실제 브랜치 이름 확인 |
| 새 파일 생성이 거부됨 | 기존 파일 존재 여부, 쓰기 권한, 브랜치 보호 규칙 확인 |
| 공개 저장소 연결이 거부됨 | 데이터 저장소를 Private으로 만들고 그 저장소를 선택 |
| 금액을 입력했는데 목록에 없음 | 내역 추가 버튼을 눌렀는지, 목록의 선택 날짜가 일치하는지 확인 |
| 저장했는데 다음 접속에서 안 보임 | 같은 연도 파일을 연결했는지 확인. 입력만 하고 내역 추가를 누르지 않았을 수도 있음 |
| 데이터 형식 오류 | `version`, `currency`, `transactions`와 각 거래 필드 확인. 다른 앱의 JSON은 바로 호환되지 않을 수 있음 |

## 8. 데이터 형식과 현재 범위

```json
{
  "version": 1,
  "currency": "KRW",
  "transactions": [
    {
      "id": "sample-transaction-001",
      "type": "expense",
      "amount": 12000,
      "date": "2026-09-10",
      "category": "식비",
      "memo": "점심 식사"
    }
  ]
}
```

위 예시는 설명용 데이터입니다. 앱에서 추가하면 고유 ID가 자동 생성됩니다. `type`은 지출 `expense`, 수입 `income`이며 `amount`는 양의 정수입니다. 토큰은 거래 파일에 저장하지 않습니다.

현재 앱은 파일당 **900,000바이트 이하**를 지원합니다. 연도별 파일이어도 거래량과 메모 길이에 따라 제한에 도달할 수 있습니다. 한도에 도달하면 구조 확장이 필요합니다.

현재 제공 범위는 연결·연도별 저장·캘린더·거래 추가·선택 날짜 목록입니다. **거래 수정·삭제, 합계 통계, 예산, 자동 병합, JSON 백업·복원 UI는 아직 없습니다.** 오류 수정이나 백업은 비공개 저장소의 JSON을 별도로 관리해야 합니다. GitHub 커밋 기록에는 이전 데이터가 남을 수 있습니다.

## 9. 업데이트 방법

화면 변경 시 수정된 HTML을 기존 파일과 같은 이름으로 업로드하고 커밋합니다. 한 페이지만 변경한 경우 해당 파일만 교체합니다. 비공개 데이터 저장소의 JSON을 웹사이트 배포 파일과 섞지 마세요.

문서 기준: 2026년 9월. 연결·생성·저장 충돌·연도 전환·날짜별 조회 등은 모의 API 테스트로 점검했으며, 실제 계정의 권한과 배포 결과는 사용 환경에서 확인해야 합니다.
