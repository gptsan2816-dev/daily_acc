# 모아 — GitHub 연동 가계부

서버 없이 동작하는 개인용 웹 가계부입니다. 화면은 GitHub Pages 같은 정적 호스팅에서 제공하고, 수입·지출 데이터는 사용자 본인의 **비공개 GitHub 저장소**에 연도별 JSON 파일로 저장합니다. 빌드 도구와 외부 라이브러리를 쓰지 않으며, 세 개의 HTML 파일이 전부입니다.

- 데이터의 소유·보관 위치는 전적으로 본인 저장소입니다.
- 네트워크 통신은 `https://api.github.com` 한 곳으로 제한됩니다(CSP `connect-src`).
- **비공개(Private) 저장소만 연결할 수 있습니다.** 공개 저장소는 연결이 거부됩니다.

## 1. 구성

| 위치 | 파일 | 역할 |
|---|---|---|
| 웹사이트 저장소 | `index.html` | GitHub 연결 화면, 새 JSON 파일 생성, 기기 저장 정보 관리 |
| 웹사이트 저장소 | `ledger.html` | 홈 화면 — 캘린더, 수입·지출 입력, 날짜별 내역 |
| 웹사이트 저장소 | `history.html` | 내역 화면 — 월별 합계와 전체 내역 |
| 웹사이트 저장소 | `README.md` | 이 문서 |
| 비공개 데이터 저장소 | `2026.json`, `2027.json` … | 연도별 거래 데이터 |

**세 HTML 파일은 같은 폴더에 두세요.** 파일 이름의 대소문자와 확장자를 그대로 유지해야 페이지 이동이 작동합니다. 업로드 과정에서 `index (1).html`이나 `index.html.txt`로 바뀌지 않았는지 확인하세요.

이 문서의 `your-github-id`, `household-ledger-data`는 설명용 예시입니다. 실제 설정에는 본인 값을 입력합니다.

## 2. 기능 요약

**연결 화면 (`index.html`)**

- 아이디·저장소·브랜치·JSON 경로·토큰 입력 후 연결
- 비공개 저장소 여부, 브랜치 존재 여부, 파일 존재 여부를 먼저 확인
- `새 파일 만들기`로 빈 가계부 JSON 생성(기존 파일은 덮어쓰지 않음)
- JSON 경로 기본값은 브라우저가 인식한 **현재 연도 + `.json`**
- 아이디·저장소·토큰의 선택적 기기 저장(`localStorage`) 및 삭제

**가계부 화면**

상단 메뉴로 **홈**(`ledger.html`)과 **내역**(`history.html`)을 오갑니다. 두 페이지는 같은 연결 정보와 미저장 내역을 공유하므로 어느 쪽에서든 저장·불러오기를 할 수 있습니다.

*홈 — `ledger.html`*

- 월간 캘린더: 이전·다음 달, 오늘, 방향키(←→↑↓)로 날짜 이동
- 캘린더 각 날짜 칸에 **일별 지출 합계(−)와 수입 합계(+)** 표시, 칸 너비에 맞춰 글자 크기 자동 축소
- 지출·수입 버튼으로 입력 폼 열기·접기, 같은 버튼을 다시 누르면 접힘
- **사람 구분**: 🍓(person1) / ⛰️(person2) 선택
- **결제수단**: 지출일 때만 표시되며 필수(신용카드·체크카드·현금·계좌이체·간편결제·기타)
- 금액 입력 시 천 단위 쉼표 자동 삽입(커서 위치 유지)
- 지출 19종·수입 9종 분류 목록
- 선택한 날짜의 내역 표: 구분 · 사람 · 분류 · 내용 · 결제수단 · 금액, 건수 표시
- **중복 방지**: 사람·날짜·구분·금액·분류·내용이 같고 지출은 결제수단까지 같으면 추가하지 않음
- 연도가 바뀌는 날짜로 이동하면 해당 연도 파일을 확인하고 없으면 생성 후 전환

*내역 — `history.html`*

- 해당 월의 지출 합계·수입 합계·합계(수입−지출)
- 사람별(🍓/⛰️/미지정) 지출·수입 합계
- 날짜별로 묶은 그 달의 전체 내역, 최근 날짜가 위
- 날짜 줄을 누르면 홈 화면에서 그 날짜가 선택됨
- 이전 달·다음 달·이번 달 이동(홈 캘린더와 같은 달을 공유)
- 아직 저장하지 않은 내역은 **미저장** 표시와 함께 목록에 포함
- 지출·수입 카드를 눌러 해당 구분만 보기(다시 누르면 전체)

*공통*

- 화면 맨 아래에 **항상 고정되는 액션 바**: 연결 상태와 미저장 건수 표시, `GitHub 저장` · `불러오기` · `연결 해제` · `파일 삭제`
- 저장 시 원격 최신 파일과 **병합 후 추가 저장**(충돌 시 최대 3회 재시도)
- 미저장 내역이나 작성 중인 입력이 있으면 페이지 이탈·연결 해제·불러오기 전에 확인
- 미저장 내역과 입력 중인 내용은 두 화면을 오가거나 새로고침해도 유지(탭을 닫으면 사라짐)

**아직 없는 기능**

개별 거래의 **수정·삭제**, 연간 합계·분류별 통계, 예산, 검색·필터, JSON 내보내기·복원 UI, 오프라인 사용. 잘못 입력한 내역은 비공개 저장소의 JSON을 직접 편집해 정리해야 합니다.

## 3. 설치 — 전체 순서

1. 웹사이트용 공개 저장소를 만들고 두 HTML 파일을 올립니다.
2. GitHub Pages를 설정합니다.
3. 데이터용 **비공개** 저장소를 만들고 README를 추가합니다.
4. 그 비공개 저장소에만 접근하는 토큰을 발급합니다.
5. 가계부 사이트에서 연결 정보를 입력합니다.
6. 처음이라면 JSON 파일을 생성하고, 기존 파일이 있다면 불러옵니다.

### 3-1. 웹사이트용 저장소 만들기

1. GitHub 로그인 후 [새 저장소 만들기](https://github.com/new)를 엽니다.
2. **Owner**에서 본인 계정을 선택합니다.
3. **Repository name**에 `daily_acc`를 입력합니다. 다른 이름도 됩니다.
4. 공개 범위를 **Public**으로 선택합니다(Pages 무료 사용 기준).
5. **Add README**를 켜고 **Create repository**를 누릅니다.
6. **Code → Add file → Upload files**에서 `index.html`, `ledger.html`, `history.html`을 업로드하고 **Commit changes**를 누릅니다.

실제 거래 데이터와 토큰은 이 저장소에 절대 올리지 마세요.

### 3-2. GitHub Pages 켜기

저장소의 **Settings → Pages → Build and deployment**에서 설정합니다.

| 항목 | 선택값 |
|---|---|
| Source | Deploy from a branch |
| Branch | `main` — 실제 파일을 올린 브랜치 |
| Folder | `/(root)` |

**Save** 후 **Actions** 탭에서 배포 완료를 확인하고 **Settings → Pages → Visit site**로 접속합니다. 저장소 이름이 `daily_acc`라면 주소는 `https://<본인아이디>.github.io/daily_acc/` 형식이며, 이 주소가 `index.html`을 표시합니다.

참고: [GitHub Pages 배포 소스 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

### 3-3. 데이터용 비공개 저장소 만들기

[새 저장소 만들기](https://github.com/new)에서 별도의 저장소를 만듭니다.

| 항목 | 입력·선택 예시 |
|---|---|
| Owner | 본인 계정 |
| Repository name | `household-ledger-data` |
| Visibility | **Private** (필수) |
| Add README | **켜기** |

생성 후 이름 옆에 **Private** 표시가 있는지 확인하세요. 앱은 연결 전에 저장소의 공개 여부를 조회하고, 공개 저장소면 연결을 거부합니다.

README를 추가해야 초기 커밋과 기본 브랜치가 만들어집니다. 앱은 기존 브랜치에 파일을 생성하므로 완전히 빈 저장소는 연결할 수 없습니다. 이 저장소에는 Pages를 설정하지 않습니다.

JSON 파일은 가계부 사이트에서 생성할 수 있으므로 직접 만들지 않아도 됩니다.

### 3-4. 접근 토큰 발급하기

[Fine-grained 토큰 발급 페이지](https://github.com/settings/personal-access-tokens/new)를 엽니다. 메뉴로 가려면 **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**입니다.

| 항목 | 설정 |
|---|---|
| Token name | `모아 가계부` 등 알아보기 쉬운 이름 |
| Expiration | 사용할 만료일 |
| Resource owner | 비공개 데이터 저장소를 소유한 본인 계정 |
| Repository access | **Only select repositories** |
| Selected repositories | `household-ledger-data` 등 **비공개 데이터 저장소** |
| Repository permissions → Contents | **Read and write** |
| Metadata | 자동 포함되는 Read-only 유지 |

**웹사이트 저장소가 아니라 데이터 저장소를 선택하세요.** 개인 계정 기준 설명이며, 조직 소유 저장소는 별도 승인이 필요할 수 있습니다.

발급된 토큰은 즉시 복사해 비밀번호 관리자 등에 보관하고, 공개 코드·JSON·스크린샷에 포함하지 마세요. 분실하거나 만료되면 새로 발급해 다시 입력합니다.

참고: [GitHub 개인 접근 토큰 공식 안내](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).

### 3-5. 사이트에서 연결하기

| 입력칸 | 예시·설명 |
|---|---|
| GitHub 아이디 | 본인 아이디 (영숫자·`_`·`.`·`-`) |
| 비공개 데이터 저장소 | `household-ledger-data` |
| 브랜치 | `main` 등 해당 저장소의 실제 브랜치 |
| JSON 파일 경로 | 현재 연도 파일, 예: `2026.json` 또는 `data/2026.json` |
| 접근 토큰 | 앞에서 발급한 토큰 |

- **파일이 이미 있는 경우:** `연결하고 시작하기`
- **파일이 없는 경우:** `새 파일 만들기` → 생성 확인 팝업 승인

`연결하고 시작하기`는 없는 파일을 만들지 않습니다. 성공하면 `ledger.html`의 홈 화면으로 이동하고 하단 상태 표시가 **GitHub 연결됨 · 파일 경로**로 바뀝니다.

직접 만들고 싶다면 비공개 저장소에서 **Add file → Create new file**로 `2026.json`을 만들고 다음을 커밋합니다.

```json
{
  "version": 1,
  "currency": "KRW",
  "transactions": []
}
```

### 3-6. 이 기기에 연결 정보 저장하기

- **이 기기에 저장:** 아이디·저장소·토큰을 이 브라우저의 `localStorage`에 보관합니다.
- **체크박스를 켠 채 연결 성공:** 같은 정보가 저장됩니다.
- **체크 해제:** 저장된 정보를 즉시 삭제합니다.
- **저장 정보 삭제:** 로컬 저장 정보와 현재 탭의 연결 세션을 지우고 입력칸을 비웁니다.

저장 대상은 아이디·저장소·토큰뿐이며, JSON 경로는 매번 올해 연도를 기본값으로 다시 채웁니다. 자동 연결은 아니므로 연결 버튼은 눌러야 합니다.

**토큰은 암호화 없이 브라우저에 저장됩니다.** 개인 기기에서만 사용하세요. 기기 저장을 선택하지 않아도, 두 페이지 사이를 이동하기 위해 현재 탭의 `sessionStorage`에 연결 정보(토큰 포함)를 보관합니다.

가계부의 **연결 해제**는 탭 세션만 지웁니다. 기기 저장 정보까지 없애려면 연결 화면의 **저장 정보 삭제**를 누르세요. 두 기능 모두 GitHub의 토큰 자체를 폐기하지는 않습니다. 폐기는 GitHub 설정에서 합니다.

## 4. 입력과 저장

1. **홈** 화면의 캘린더에서 날짜를 선택합니다.
2. **지출** 또는 **수입** 버튼을 누릅니다.
3. 사람(🍓 / ⛰️)을 고르고 날짜·금액·분류·내용을 입력합니다. 지출이면 결제수단도 선택합니다.
4. **지출 추가 / 수입 추가**를 누릅니다. → 화면과 캘린더 합계에 즉시 반영됩니다.
5. 아래 목록에서 내용을 확인합니다.
6. 하단 **GitHub 저장**을 누릅니다.

### 알아둘 점

- **‘내역 추가’와 ‘GitHub 저장’은 다릅니다.** 입력칸만 채운 상태로 GitHub 저장을 누르면 그 내용은 저장되지 않습니다. 먼저 내역 추가를 누르세요.
- 입력 폼의 날짜를 직접 바꾸면 캘린더 선택도 함께 이동합니다.
- 지출·수입을 전환하면 금액·내용은 유지되고 분류 목록과 결제수단 표시가 바뀝니다. 추가 전에 확인하세요.
- 폼을 접어도 작성 중인 내용은 유지됩니다.
- 금액은 `12,000`처럼 표시되지만 JSON에는 숫자로 저장됩니다. 범위는 1원 ~ 1조 원의 정수입니다.
- 내용(메모)은 필수이며 200자, 분류는 100자까지입니다.
- 이미 같은 내역이 있으면 “동일한 내역이 있어 추가하지 않았습니다”가 표시되고 추가되지 않습니다.
- 미저장 내역이 있으면 하단 상태에 `저장 필요 N건`이 표시되고, 페이지를 벗어날 때 브라우저가 경고합니다.
- 거래 내역은 로컬에 자동 백업되지 않습니다.

### 저장 동작

`GitHub 저장`은 원격 파일의 최신 내용을 다시 읽어 **미저장 내역만 덧붙여 저장**합니다.

- 다른 기기에서 추가된 내역은 지워지지 않고 함께 유지됩니다.
- 저장 도중 충돌(409/422)이 나면 최신 내용을 다시 읽어 최대 3회까지 재시도합니다.
- 원격에 이미 같은 내용이 있으면 중복으로 건너뛰고 `중복 N건 제외`로 알려 줍니다.
- 같은 ID의 내역이 원격에서 다르게 바뀌어 있으면 저장을 중단하고 미저장 내역을 그대로 유지합니다.
- 병합은 **추가 방향만** 처리합니다. 원격에서 삭제·수정된 내용을 되돌리거나 반영하지는 않습니다.

## 5. 월별 내역 보기

상단 메뉴의 **내역**을 누르면 `history.html`로 이동해 그 달의 전체 내역을 한 화면에서 봅니다. 홈으로 돌아올 때는 메뉴의 **홈** 또는 브라우저 뒤로 가기를 사용합니다.

| 영역 | 내용 |
|---|---|
| 요약 카드 | 이 달의 지출 합계, 수입 합계, 합계(수입 − 지출). 누르면 구분 필터로 동작 |
| 사람별 합계 | 🍓 / ⛰️ / 미지정 각각의 지출·수입 합계. 해당 내역이 있을 때만 표시 |
| 날짜 묶음 | 최근 날짜부터, 각 줄에 건수와 그날의 지출(−)·수입(+) 합계 |
| 내역 줄 | 구분 · 내용 · 분류 · 결제수단 · 사람 · 금액. 저장 전 내역에는 **미저장** 표시 |

- **이전 달 / 다음 달 / 이번 달** 버튼으로 이동하며, 홈 캘린더와 같은 달을 공유합니다. 한쪽에서 달을 바꾸면 다른 쪽도 같은 달을 봅니다.
- **지출 카드나 수입 카드를 누르면** 그 구분의 내역만 보입니다. 같은 카드를 다시 누르거나 합계 카드를 누르면 전체로 돌아옵니다. 필터는 달을 옮기거나 홈에 다녀와도 유지됩니다.
- 필터를 켜면 목록·날짜별 합계·사람별 합계가 그 구분만 반영합니다. **요약 카드 세 개는 항상 그 달 전체 금액**을 보여 줍니다.
- **날짜 줄을 누르면** 홈 화면으로 이동해 그 날짜가 선택됩니다.
- 홈에서 추가한 미저장 내역도 함께 보이며, 이 화면의 **GitHub 저장**으로 바로 저장할 수 있습니다.
- 다른 연도의 달로 이동하면 홈과 동일하게 해당 연도 파일을 확인·생성하며, 미저장 내역이 있으면 먼저 저장해야 합니다(6장).

내역 추가는 홈 화면에서만 합니다. 이 화면의 액션 바에는 `연결 해제` · `GitHub 저장` · `불러오기`가 있고, **파일 삭제는 홈 화면에만** 있습니다.

## 6. 연도가 바뀔 때

캘린더 이동이나 날짜 입력으로 다른 연도의 날짜를 선택하면 같은 저장소·브랜치에서 그 연도의 파일을 확인합니다. 경로가 `data/2026.json`이면 다음 파일은 `data/2027.json`입니다.

| 상태 | 동작 |
|---|---|
| 미저장 내역이 있음 | 안내 후 전환하지 않음. 먼저 **GitHub 저장**을 눌러야 함 |
| `2027.json`이 있음 | 바로 불러오고 건수를 알림 |
| `2027.json`이 없음 | 생성 여부를 묻고, 승인하면 빈 파일을 만든 뒤 불러옴 |
| 생성 팝업에서 취소 | 기존 연도와 날짜 유지 |
| 입력칸에 작성 중인 내용이 있음 | 내용을 유지한 채 날짜만 변경 |
| 권한·네트워크 오류 | 오류 안내 후 기존 연결 유지 |

여러 연도를 담은 예전 파일을 자동으로 연도별로 분리하거나 이전하지는 않습니다. 또한 입력 폼의 날짜는 현재 불러온 연도와 같아야 추가할 수 있습니다.

## 7. 불러오기·연결 해제·파일 삭제

- **불러오기:** 연결된 JSON의 최신 내용을 다시 가져옵니다. 미저장 내역이나 작성 중인 내용이 있으면 버릴지 확인합니다.
- **연결 해제:** 탭 세션을 지우고 연결 화면으로 돌아갑니다. 기기 저장 정보는 남습니다.
- **파일 삭제:** 연결된 JSON 파일 자체를 저장소에서 삭제합니다. 확인 창에 **파일 경로를 정확히 입력해야** 진행되며, 화면에서 확인한 파일 버전과 원격 버전이 다르면 삭제하지 않습니다. 삭제 후에는 연결 화면으로 이동합니다. **GitHub 커밋 기록에는 이전 데이터가 남습니다.**

네트워크 오류로 저장·삭제 결과를 확인하지 못했을 때는 GitHub에서 실제 파일 상태를 먼저 확인하세요.

## 8. 데이터 형식

```json
{
  "version": 1,
  "currency": "KRW",
  "transactions": [
    {
      "id": "6f1f8b02-2f0a-4f1e-9a2f-3f1c2a7d0b91",
      "type": "expense",
      "amount": 12000,
      "date": "2026-09-10",
      "category": "식비",
      "memo": "점심 식사",
      "person": "person1",
      "paymentMethod": "신용카드"
    }
  ]
}
```

| 필드 | 필수 | 규칙 |
|---|---|---|
| `version` | 예 | `1` 고정 |
| `currency` | 예 | `"KRW"` 고정 |
| `transactions` | 예 | 배열 |
| `id` | 예 | 비어 있지 않은 문자열, 파일 안에서 고유. 앱에서 추가하면 UUID 자동 생성 |
| `type` | 예 | `"expense"` 또는 `"income"` |
| `amount` | 예 | 1 이상 1,000,000,000,000 이하의 정수 |
| `date` | 예 | `YYYY-MM-DD`, 실재하는 날짜 |
| `category` | 예 | 1~100자 |
| `memo` | 예 | 200자 이하(빈 문자열 허용, 앱 입력은 필수) |
| `person` | 아니오 | `"person1"`(🍓) 또는 `"person2"`(⛰️). 없으면 목록에 `미지정` |
| `paymentMethod` | 아니오 | 100자 이하 문자열. 앱에서 지출 추가 시 자동 기록, 수입에는 저장하지 않음 |

형식에 맞지 않는 항목이 하나라도 있으면 파일 전체를 불러오지 않고 원본도 변경하지 않습니다. 토큰은 거래 파일에 저장되지 않습니다.

**파일 크기 한도는 900,000바이트**입니다. 읽기·쓰기 양쪽에 적용되며, 초과하면 저장이 거부됩니다. 연도별 파일이어도 거래량과 메모 길이에 따라 도달할 수 있습니다.

## 10. 자주 발생하는 문제

| 증상 | 확인할 내용 |
|---|---|
| Pages 주소에서 404 | 파일 이름이 정확히 `index.html`인지, 배포 브랜치 최상위에 있는지, Pages가 같은 브랜치와 `/(root)`인지 |
| 이전 화면이 계속 표시 | Actions 배포 완료 후 새로고침, 필요하면 강력 새로고침 |
| 가계부 페이지가 연결 화면으로 되돌아감 | 탭 세션이 없거나 읽을 수 없는 상태. 연결 화면에서 다시 연결 |
| “비공개 저장소만 연결할 수 있습니다” | 데이터 저장소를 Private으로 바꾸거나 새로 만들어 연결 |
| 401 오류 | 토큰 만료·오타·폐기 여부 |
| 403 오류 | Contents `Read and write` 권한, 조직 승인, API 사용 한도 |
| 404 오류 | 아이디·저장소·브랜치·경로, 그리고 토큰이 그 저장소를 선택했는지. 권한 부족도 404로 보일 수 있음 |
| 브랜치를 확인할 수 없음 | 브랜치 이름 확인. 완전히 빈 저장소라면 README를 먼저 추가 |
| 새 파일 생성이 거부됨 | 같은 경로에 파일이 이미 있는지, 쓰기 권한, 브랜치 보호 규칙 |
| 저장 시 “같은 ID의 내역이 변경되었습니다” | 다른 곳에서 같은 거래를 수정함. 미저장 내역을 따로 기록하고 불러오기 후 재입력 |
| 결제수단을 선택할 수 없음 | 수입에는 결제수단이 없습니다. 지출에서만 표시됩니다 |
| 금액을 입력했는데 목록에 없음 | 내역 추가 버튼을 눌렀는지, 목록의 선택 날짜가 맞는지, 중복 안내가 뜨지 않았는지 |
| 연도를 바꿀 수 없음 | 미저장 내역을 먼저 GitHub 저장 |
| 내역 화면이 비어 있음 | 보고 있는 달, 그 달의 내역 유무, 그리고 **지출·수입 필터가 켜져 있는지** 확인 |
| 내역 화면에서 연결 화면으로 돌아감 | 탭 연결 세션이 없는 상태. 첫 화면에서 다시 연결 |
| 내역 화면에 홈에서 추가한 내역이 없음 | 두 파일이 같은 폴더·같은 사이트 주소에 있는지 확인. 다른 탭에서 열면 연결 세션이 공유되지 않음 |
| 저장했는데 다음 접속에 안 보임 | 같은 연도 파일을 연결했는지 |
| 데이터 형식 오류 | 8장의 필드 규칙 확인. 다른 앱의 JSON은 바로 호환되지 않습니다 |
| 900KB 초과 | 백업 후 기간을 나눠 별도 파일·저장소로 분리 |

## 11. 개발과 배포

빌드 과정이 없습니다. 파일을 열어 편집하고 그대로 올리면 됩니다.

- 로컬 확인: 세 파일을 같은 폴더에 두고 `python3 -m http.server` 같은 정적 서버로 엽니다. `file://`로 열면 저장소 저장 기능이 제한될 수 있습니다.
- 배포: 수정한 HTML을 같은 이름으로 업로드해 커밋합니다. 한 페이지만 바꿨다면 그 파일만 교체합니다.
- 홈(`ledger.html`)과 내역(`history.html`)은 별도 페이지이며, 같은 탭의 `sessionStorage`로 상태를 주고받습니다.

  | 키 | 내용 |
  |---|---|
  | `moa.github.session.v1` | 연결 정보(아이디·저장소·브랜치·경로·토큰) |
  | `moa.pending.v1` | 저장하지 않은 거래 목록 |
  | `moa.entry.draft.v1` | 홈의 입력 중인 내용 |
  | `moa.view.month.v1` | 두 화면이 공유하는 표시 중인 달 |
  | `moa.view.date.v1` | 내역에서 홈으로 넘길 날짜(홈이 읽고 즉시 삭제) |
  | `moa.view.filter.v1` | 내역의 구분 필터(`expense` / `income`, 전체일 때는 없음) |

  두 페이지는 GitHub API 호출·검증 코드를 각자 복사해 가지고 있습니다. 연결이나 저장 로직을 고칠 때는 세 파일을 함께 확인하세요.
- 세 파일은 각각 자체 CSS·스크립트를 포함하는 독립 문서입니다.
- 비공개 데이터 저장소의 JSON을 웹사이트 배포 파일과 섞지 마세요.

문서 기준: 2026년 9월, `index.html`·`ledger.html` 현재 구현. 실제 계정의 권한과 배포 결과는 사용 환경에서 확인해야 합니다.
